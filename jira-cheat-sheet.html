Jira Cheat Sheet for Agile Teams

How the toolkit's practices show up in Jira Cloud. CM = company-managed project · TM = team-managed project.

ONE SIDE · JIRA CLOUD

1Work Hierarchy → The ToolkitJira now calls issues "work items"

Above epic · Premium / PlansInitiativeA strategic bet across teams. Shape it with the Epic Breakdown Canvas before it becomes epics.
Level 1EpicOne hypothesis, an MVP and 3–8 features. Weeks to a quarter. Put the hypothesis and success measure in the description.
Level 0 · Story · Task · BugStoryA vertical slice of value that fits in a sprint. Lay them out with the Story Map, size them with Story Splitting, confirm with Example Mapping.
Level −1 · optionalSub-taskThe team's how-to steps for one story. Never a separate slice of value, and never tracked as progress.

Several teams? Some add a Feature level between epic and story (part of SAFe), or treat epics as features. Pick one mapping and write it down.

2Board SetupMake the real flow visible

  • Columns = real states. One column for each place work actually waits or changes hands. Add a Waiting for review column so queues show.
  • WIP limits. Set a maximum on in-progress columns. CM: Board settings → Columns. TM: column menu → Set column limit.
  • Swimlanes. By epic or by query, with an Expedite lane for urgent work. Avoid lanes by person.
  • Quick filters. CM: any JQL, e.g. flagged is not EMPTY. TM: built-in filters for epic, type, assignee and label.
  • Days in column. CM: Card layout → show days in column, so ageing work stands out.
  • Done means Done. Only the last column maps to the Done category, and nothing moves there until it meets the Definition of Done.

3Sprint OperationsPlan · run · close

  • Refine. Keep 1–2 sprints of stories ready at the top of the backlog. Rank by dragging. The order is the plan.
  • Start. Fill in the Sprint goal field in the Start sprint dialog. It then shows on the board for everyone.
  • Run. Flag blocked work (right-click → Add flag) and raise it at the Daily Scrum. Walk the board right to left.
  • Close. Complete sprint asks where unfinished work goes. Decide each item on purpose: next sprint, or back to the backlog to re-rank.

4JQL You'll ReuseReplace KEY with your project key

Open sprint, not doneproject = KEY AND sprint in openSprints() AND statusCategory != Done
Stale in progressproject = KEY AND statusCategory = "In Progress" AND updated <= -5d
Blockedproject = KEY AND flagged is not EMPTY
Stories with no epicproject = KEY AND issuetype = Story AND parent is EMPTY
Ready but unestimatedproject = KEY AND issuetype = Story AND statusCategory = "To Do" AND "Story point estimate" is EMPTY CM field: "Story Points"
Backlog graveyardproject = KEY AND statusCategory = "To Do" AND created <= -180d ORDER BY created ASC
Finished in the last 2 weeksproject = KEY AND statusCategory = Done AND statusCategoryChangedDate >= -14d
Started in the last 2 weeksproject = KEY AND status CHANGED TO "In Progress" AFTER -14d

Scope added mid-sprint has no clean JQL: use the Sprint Report (added items are marked *). Save queries as shared filters.

5Reports & What They Tell YouUse them for questions, not judgement

Sprint ReportCommitted vs. completed, plus scope added (*) and removed.“What changed our plan, and could we have seen it coming?”
Burndown / BurnupProgress inside a sprint. A flat line then a cliff means big items or testing left to the end.“What would let work finish earlier in the sprint?”
VelocityA forecasting aid for this team only. Never compare teams or set it as a target.“What range can we plan with?”
Cumulative FlowA widening band is a bottleneck; rising bands with flat Done mean too much WIP.“Where is work piling up?”
Control Chart · CMCycle time per item, with outliers and trend. TM projects: use the cycle time report where available.“What happened to the outliers?”
Epic & Version ReportsForecast a completion range from remaining work and velocity.“What could we cut to land sooner?”

6Jira Anti-PatternsSpot it · Try this

Status theatreTickets updated just before the stand-up, not as work moves.Walk the board at the Daily Scrum and update as you go.
Workflow sprawlTwelve statuses and forty custom fields nobody reads.One status per real wait or hand-off. Prune fields every quarter.
Horizontal sub-tasksFront end, back end and QA sub-tasks presented as progress.Split stories vertically with the splitting patterns.
Tickets as performancePeople ranked by tickets closed or points burned.Measure team outcomes and flow, never individuals.
Jira as the conversationRequirements argued out in long comment threads.Talk first (try Example Mapping), then record the decision.
Backlog graveyardHundreds of items, the oldest years old.Archive anything untouched for 6 months. It'll come back if it matters.
