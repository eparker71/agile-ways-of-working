User Story Map Guide

How to map a user journey and slice it into releases that each deliver a complete, usable path.

Facilitator Run-Sheet · Break Down Work · Inspired by Jeff Patton's Story Mapping

“What's the smallest slice that lets a user reach their goal end-to-end?”

A flat backlog hides the big picture. A story map arranges work along the user's journey: the activities across the top form the backbone, the user tasks beneath them form the walking skeleton, and stories hang below each task. Horizontal release slices then show what's in the MVP, what comes next, and what can wait. Each slice is a complete path a user can actually use.

1Before the session

  • Print the board at A1 or A0 if you can, or use a long wall or digital board, as maps grow wide
  • Blue, yellow and green stickies, markers, and tape to mark slice lines
  • Agree the persona and goal in advance, or plan to start with them
  • Bring user research, journey maps or support data if you have them
  • If the product is large, scope the map to one persona and one goal

2Agenda & run-sheet

TimeActivityFacilitator notes
0–10Persona & goalFill in the context bar: who is the user, what are they trying to achieve, and which product or epic is this?
10–301 · ActivitiesTell the user's story out loud, left to right. Write each big step as a blue sticky in the backbone. Aim for 4–10.
30–552 · User tasksUnder each activity, add the yellow steps the user takes. Walk the whole skeleton end-to-end to check that nothing is missing.
55–90StoriesBrainstorm green stories under each task: options, variations, details. Order each column, most important at the top.
90–110Slice the MVPDraw the Release 1 line: the fewest stories that still let a user complete the journey end-to-end. Write its outcome.
110–125Next slicesSlice Release 2 and Later. Give each slice an outcome and a target date.
125–135Check & closeWalk the MVP slice as the user. Can they reach their goal? Agree the next step: splitting and refinement.

3Using each part of the map

What goes where, and what to watch for.

Context bar

  • One persona and one goal per map
  • Write the product or epic it serves

1 · Activities

  • Verb phrases: “Find a product”, “Pay”
  • In the order users do them
  • 4–10 is typical

2 · User Tasks

  • The steps within each activity
  • Together they form the walking skeleton
  • Read them left to right as a story

Stories

  • Hang under the task they belong to
  • Most important at the top
  • Variations and details go lower

Release 1 · MVP

  • At least one story under every task
  • The thinnest path to the goal
  • Has a clear outcome

Release 2 & Later

  • Make the journey better or broader
  • Revisit after learning from Release 1

4Facilitation tips

Tell it as a storyNarrate the journey: “first the user…, then…”. Gaps become obvious when you say them out loud.
Breadth before depthGet the whole backbone in place before adding detail anywhere. It's easy to over-detail the first activity.
Every column in the MVPAn MVP that skips a task isn't usable end-to-end. Even a manual or basic version counts.
Slice by outcomeName what each release lets users do or learn, not just which stories it contains.
Keep it visibleLeave the map on the wall and update it each sprint. It becomes the team's shared picture of the product.
One map per goalIf the map sprawls, you probably have more than one persona or goal. Split it.
Common pitfalls: mapping system components instead of user steps; spending all the time on one activity; an MVP that is everything in the first two columns; never revisiting the map after the workshop; stories that are really tasks.

5After the session

Straight away

Photograph the map in sections. Transfer stories to the backlog, keeping their slice and order.

Refine

Split any Release 1 story that is too big using the Story Splitting poster, then use Example Mapping on each.

Each sprint

Move completed stories, adjust slices as you learn, and review the map at Sprint Review.

After release

Check the slice's outcome. Did users reach their goal? Re-slice what's next.

6How it fits the toolkit

The break-down tools work from big to small: the Epic Breakdown Canvas turns an idea into an MVP and features, the Story Map lays out the user journey and release slices, the Story Splitting poster makes stories small enough for a sprint, and Example Mapping checks that each story is understood and ready. Purpose: Map the user's journey, then slice it into releases that each deliver a complete, usable path.

Layout: a wide landscape board (about 16:11). Make one frame per section below, placed as described. In each frame, add the section name as a heading, then its content as short text labels or empty fields to fill in. Leave space in each frame for sticky notes. Use the header colour given. Keep the wording as written and don't add extra content.
Key: Blue Sticky = Activity (backbone) · Yellow Sticky = User Task · Green Sticky = Story / Detail
