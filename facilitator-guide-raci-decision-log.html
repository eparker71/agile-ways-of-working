“Who is accountable for this, just one person?”

Confusion about roles slows projects down: work falls between people, or several people think they decide. A RACI matrix lists the work, deliverables or decisions, and for each role marks who is Responsible (does it), Accountable (owns the outcome, exactly one person), Consulted (gives input) and Informed (kept up to date). The decision log records key decisions, the options considered and why, so the same debates don't restart every month. Use it alongside the Delegation Board, which covers how much a team decides.

1Before the session

  • Print the board at A3, or load the SVG as a digital background
  • List the main work items, deliverables and decisions in advance
  • List the roles (not names, where possible): sponsor, product owner, team lead, architect and so on
  • Invite the people in those roles, so they agree to what's assigned

3Making it work

Quality checks for the matrix and the log.

Responsible

  • Does the work
  • Can be several people

Accountable

  • Owns the outcome
  • Exactly one person

Consulted

  • Gives input before
  • Keep the list short

Informed

  • Told after
  • No input expected

Decision Log

  • Options and reasons
  • A revisit trigger

4Facilitation tips

One A, alwaysShared accountability means no accountability. Pick one person.
Watch the CsEvery consulted person adds delay. Make some of them Informed instead.
Roles, not namesUse roles so the matrix survives people changing.
Agree, don't assignPeople named on the matrix should agree to it, or it won't hold.
Log the whyRecording why a decision was made is more useful than the decision itself.
Set revisit triggersSay what would make you revisit a decision, such as new data or a budget change.
Common pitfalls: two As on a row; everyone Consulted on everything; a matrix nobody agreed to; using RACI to avoid conversations; a decision log with no reasons; never updating either.

5After the session

Straight away

Share the matrix with everyone named and store it with the project.

Each decision

Add it to the log within a day, with the options and the reasons.

When people change

Review the matrix with new role holders.

At project close

Use the decision log in the lessons-learned session.

6How it fits the toolkit

The project tools work together: run a Project Kickoff first, then build the Stakeholder Map, keep the RAID Log up to date, and refresh the Release Forecast after every iteration. Inside the project, teams use the lifecycle tools (Team Charter, Prioritisation, Sprint Planning and Review) and the break-down tools.
