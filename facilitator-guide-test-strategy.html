“How would we know, within minutes, that we'd broken something?”

Quality can't be tested in at the end; it's built in all the way through. The test pyramid, popularised by Mike Cohn, is a simple guide: have many fast unit tests, fewer integration tests, a small number of slow end-to-end tests, and exploratory testing by people for what scripts can't find. Shift left means finding problems earlier, when they're cheap to fix: agreeing examples before coding, and checking security, accessibility and performance as you go rather than at the end. The board helps the whole team, not just testers, agree how quality is built in and who owns each part.

3The four levels

Push each test as low down the pyramid as it can go.

Unit

  • Small pieces of code
  • Thousands, in seconds
  • Written with the code

Integration / API

  • Services together
  • Contracts between teams

End-to-end / UI

  • Key user journeys only
  • Slow and brittle if overused

Exploratory

  • People exploring
  • Finds what no one thought of

Quality Gates

  • Automated where possible
  • Block only for real risks

4Facilitation tips

Quality is the team's jobDevelopers, testers and the product owner all own quality; testers bring the expertise.
Watch the shapeLots of slow end-to-end tests and few unit tests (an ice-cream cone) makes feedback slow and flaky.
Fix flaky tests fastA test that fails at random teaches people to ignore red builds.
Test by riskSpend most effort where a bug would hurt users or the business most.
Examples firstAgreeing examples in refinement or Example Mapping prevents many bugs before any code exists.
Keep people exploringAutomation checks what you expect; exploratory testing finds what you didn't.
Common pitfalls: leaving testing to the end, or to testers alone; chasing a coverage number instead of risk; too many slow UI tests; ignoring flaky tests; quality gates that block for everything, so people work around them.

5After the session

Straight away

Update the Definition of Done and add the shift-left practice to working agreements.

Each iteration

Spend the agreed time on test debt.

Monthly

Check how many bugs escaped, and where they could have been caught.

Quarterly

Revisit the pyramid and the gates as the product changes.
