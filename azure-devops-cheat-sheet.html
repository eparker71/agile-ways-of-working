Azure DevOps Cheat Sheet for Agile Teams

How the toolkit's practices show up in Azure Boards, Repos and Pipelines. Menu names and state names vary by process and version, so check your own project.

ONE SIDE · AZURE DEVOPS SERVICES

1Work Hierarchy → The ToolkitSet by the process you chose

Portfolio backlogEpicA big bet across teams and quarters. Shape it with the Epic Breakdown Canvas: hypothesis, MVP, success measure.
Portfolio backlogFeatureA capability users can see, delivered over a few sprints. Built in to the Agile, Scrum and CMMI processes, so you don't need SAFe to have it.
Requirement backlogUser Story · PBICalled User Story (Agile), Product Backlog Item (Scrum), Requirement (CMMI) or Issue (Basic). A vertical slice that fits a sprint: see Story Splitting.
Sprint backlogTaskThe team's how-to steps for one story. Remaining-work hours are optional; many teams skip them.

Teams own work through area paths; sprints are iteration paths. Add or rename backlog levels in an inherited process (Organization settings → Process). Write your mapping down once.

2Board SetupMake the real flow visible

  • Columns = real states. Board settings (gear) → Columns. Add one for each real wait or hand-off, mapped to a state.
  • WIP limits. Each column has a WIP limit; the count turns red when it's exceeded.
  • Split columns. Turn on Doing / Done in a column so queues waiting for the next step show.
  • Definition of Done. Each column has a Definition of done box, shown on the board. Use it for exit policies.
  • Swimlanes. Add an Expedite lane for urgent work. Avoid lanes by person.
  • Card styles. Rules that colour cards, e.g. changed more than 5 days ago, so ageing work stands out.

3Sprint OperationsPlan · run · close

  • Set up. Project settings → Team configuration → Iterations: pick the team's sprints. Set areas there too.
  • Plan. Drag items to the sprint from the backlog, and use the Capacity tab for days off. There's no sprint goal field: put the goal in a Markdown widget on the team dashboard.
  • Run. Walk the board right to left. Tag blocked items Blocked and raise them at the Daily Scrum.
  • Close. Unfinished items stay in the old sprint until moved. Decide each one on purpose: next sprint, or back to the backlog.

4Queries You'll ReuseWIQL clauses · Agile process state names

This sprint, not done[System.IterationPath] = @CurrentIteration AND [System.State] NOT IN ('Closed', 'Removed')
Stale in progress[System.State] = 'Active' AND [System.ChangedDate] <= @Today - 5
Blocked[System.Tags] CONTAINS 'Blocked' A tag the team agrees to use.
My team's work[System.AreaPath] IN @TeamAreas
Stories with no featureQuery type Work items and direct links → return items that don't have a matching Parent link.
Backlog graveyard[System.State] = 'New' AND [System.CreatedDate] <= @Today - 180
Finished in the last 2 weeks[Microsoft.VSTS.Common.ClosedDate] >= @Today - 14
Started in the last 2 weeks[Microsoft.VSTS.Common.ActivatedDate] >= @Today - 14

Scrum process: in progress is Committed and finished is Done. Build queries in the editor, then save them as shared queries.

5Analytics & What They Tell YouUse them for questions, not judgement

Sprint BurndownProgress inside a sprint, by count of items or remaining work.“What would let work finish earlier in the sprint?”
VelocityA forecasting aid for this team only. Never compare teams or set it as a target.“What range can we plan with?”
Cumulative FlowA widening band is a bottleneck; rising bands with a flat Done band mean too much WIP.“Where is work piling up?”
Cycle Time & Lead TimeDashboard widgets showing each item's time, with outliers.“What happened to the outliers?”
Delivery PlansSeveral teams' work on one timeline, with dependency lines.“Which dependency could we remove?”
DashboardsOne page per team: the goal, flow, blockers and quality.“What would we look at every day?”

6Azure DevOps Anti-PatternsSpot it · Try this

Hours over outcomesRemaining-work hours on every task, reviewed as performance.Track items finished, not hours burned.
Process sprawlAn inherited process with dozens of custom fields and states.One state per real wait. Prune fields every quarter.
Feature dumping groundFeatures that never close, collecting stories for months.Give each feature an outcome and a finish line.
Area path mazeTeams can't tell what's theirs.One area per team; shared areas only on purpose.

7Repos & PipelinesDevOps in the same tool

  • Branch policies. On main: required reviewers, build validation and linked work items. Keep pull requests small and short-lived.
  • Link the work. Mention #123 in a commit or PR to link work item 123, so stories show their code.
  • Environments. Put approvals and checks on production in Pipelines, and match approval to risk.
  • Wiki. Keep the working agreement, Definition of Done and decisions (ADRs) in the project wiki, and link them from the team dashboard.
  • Measure it. Deployment frequency and failures come from pipeline runs: see Delivery Metrics, Pipeline Canvas and CD Health Check.
