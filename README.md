# Agile Ways of Working Toolkit

Printable boards and facilitator guides for teams and facilitators.

**Live site:** https://eparker71.github.io/agile-ways-of-working/

To browse everything locally, open `index.html`. Terms are defined in `glossary.html`, and `anti-patterns.html` is a searchable catalogue of 42 common anti-patterns with what to try. `scenarios.html` is the **Scenario Playbook**: a running list of common situations (a deadline moves earlier, a key person leaves…) with first moves, longer-term fixes and tools. Add to it by editing `_content/scenarios.md`, or suggest one through a GitHub issue. Not sure where to start? Open `start-here-by-role.html`, or use the **I'm a…** role filter at the top of the home page. It covers Scrum Masters, coaches, product owners, project, program and portfolio managers, executives, engineering managers, designers and team members.

Each board comes as:
- **`.html`**: view in a browser or print. Boards print at A3 landscape; guides print at A4 portrait.
- **`.svg`**: import into Miro, Mural or FigJam as a locked background, or edit it in Figma, Inkscape or Illustrator.

Each generated facilitator guide also comes as an editable **Word (`.docx`)** file. Every guide also has a **"Recreate it in your whiteboard"** section: an AI prompt, read automatically from the board, that you can paste into Miro AI, Atlassian Rovo or another assistant to build an editable, native version of the board.

## How the tools fit together

The home page groups tools by what you're trying to do. No one framework is assumed: take any tool from the box.

| Section | Tools |
|---|---|
| Set up the team | Team Launch (Sprint Zero), Team Charter, AI Working Agreement, Skills Matrix |
| Decide what to build | Product Vision Board, Persona & Journey Map, Opportunity Solution Tree, Impact Map, Prioritisation Board |
| Break down work | Epic Breakdown Canvas, User Story Map, Story Splitting, Example Mapping, Backlog Item Anatomy, Estimation |
| Run events & iterations | Events & Cadences poster, Sprint Planning, Daily Sync, Backlog Refinement, Sprint Review |
| Manage flow | Kanban Board Design, Kanban Cadences, Ageing WIP & SLE, Buffering & Swarming, Blocker Clustering, Impediments Board, Value Stream Map |
| Engineering practices | SDLC at a Glance, Delivery Pipeline Canvas, Test Strategy, Release Readiness & Strategy, Continuous Delivery Health Check, Pairing & Mobbing, Delivery Metrics & Tech Debt, Architecture Decision Record, Blameless Incident Review |
| Reflect & improve | Retrospective Kit, Team Health Check, Psychological Safety Check, Anti-Pattern Spotter, Marginal Gains Workshop, 1% Experiment Canvas, Root Cause Analysis |
| Run a project | Right-Size Your Structure, Project Kickoff, Stakeholder Map, Pre-mortem, RAID Log, RACI & Decision Log, Release Forecast & Burn-up, Outcome Status Report |
| Coordinate teams | Objectives & Key Results, Cross-Team Planning, Dependency Map, Cross-Team Sync, Team Topology Design, Cross-Team Retro |
| Lead the organisation | Value Metrics, Portfolio Kanban & Investment Mix, Delegation Board, Leading for Psychological Safety, ADKAR Change Readiness (ADKAR® is a registered trademark of Prosci, Inc.) |
| Facilitate & coach | Facilitation Techniques, Lean Coffee, Coaching Conversation |

The home page also has a **Start here** strip (role guide, glossary, cheat sheets, Make It Yours), a sticky section menu, a search box and the **I'm a…** role filter.

**Diagnose** (Team Health Check) → **Explore** (Marginal Gains Workshop) → **Experiment** (1% Experiment Canvas) → **Reflect** (Retrospective Kit), then back round again. Lean Coffee and the Facilitation Techniques poster can be used at any point. The Psychological Safety Check sits alongside the Health Check, and the Coaching Conversation canvas supports one-to-one coaching.

**Breaking down work** goes from big to small: Epic Breakdown Canvas (idea → MVP → features) → User Story Map (journey → release slices) → Story Splitting (stories small enough for a sprint) → Example Mapping (is each story understood and ready?). The Backlog Item Anatomy poster shows what a good epic, feature and story look like.

## Editing and regenerating

Most files are generated by scripts in `_generator/`. Edit the scripts rather than the generated files, because edits to generated files are overwritten on the next run.

```sh
python3 _generator/build_all.py     # run every generator, in order (build_meta.py last)
python3 _generator/check_site.py    # check links, metadata, files and the cheat sheets
```

The individual generators are `build_boards.py`, `build_guides.py`, `build_roles.py`, `build_glossary.py`, `build_antipatterns.py`, `build_scenarios.py`, `build_recipes.py` and `build_meta.py`; `build_all.py` runs them in the right order.

**Automated checks:** on every push and pull request, GitHub Actions (`.github/workflows/checks.yml`) rebuilds the site, fails if the committed files don't match what the generators produce, and runs `check_site.py`.

- `brand.py` holds the brand: accent and header colours, fonts and the credit line. All four generators read it, so rebranding is one edit.
- `build_boards.py` holds the shared visual components (header, panels, sticky zones, action cards, footer). Boards don't assume a cadence: where a period matters, they leave a blank to write in (sprint, month, quarter). The old `-sprint` / `-quarter` page names redirect to the single boards (`REDIRECTS`).
- `build_recipes.py` makes `workshop-recipes.html` from `_content/recipes.md`: ready-made agendas that combine tools (each step is `length | tool title | what happens`), plus the worked examples.
- Worked examples (`worked-example-*.html/svg`) are made by `build_boards.py` (`EXAMPLES`): each reads a generated blank board and adds a layer of handwriting and sticky notes for the fictional "Basket team". Their guides link to them automatically.
- `build_meta.py` runs last. It adds a description, link-preview (Open Graph) tags, a canonical URL and the favicon to every page, and writes `sitemap.xml`, `robots.txt` and `404.html`. The preview image `og-image.png` is made from `_generator/og-card.html`.
- `board_spec.py` reads a board's SVG (panels, positions, colours and text) and turns it into the whiteboard prompt shown in each guide.
- `build_guides.py` holds each guide's content in the `GUIDES` list. It copies its styling from `facilitator-guide-marginal-gains.html`, and writes a Word copy of each guide with `docx_writer.py` (standard library only).
- `build_roles.py` holds the `ROLES` table: which tools suit each role. It writes `start-here-by-role.html`, tags each `index.html` card with `data-roles`, and builds the home page's sticky section menu (from the `<h2 id>` headings; short labels in `SHORT`), search box and role filter. Re-run it after adding a card or section.
- `build_glossary.py` holds the `TERMS` list (definition, framework note, related tools). Links use the `TOOLS` table from `build_roles.py`.
- These files are hand-written and are not overwritten by the scripts: the Marginal Gains boards, `facilitator-guide-marginal-gains.html`, `scrum-master-agile-coach-cheat-sheet.html`, `jira-cheat-sheet.html`, `make-it-yours.html` and `index.html` (apart from the role tags and filter, which `build_roles.py` maintains).

When you add a new board, also add a guide entry to `GUIDES`, a card to `index.html`, and the tool to `TOOLS` and the relevant roles in `build_roles.py`.
